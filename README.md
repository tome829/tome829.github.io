# 함께 피어나는 날 · 모바일 청첩장

HTML5, CSS3, Vanilla JavaScript로 제작한 빌드 없는 모바일 청첩장입니다. 외부 프레임워크·폰트·백엔드·DB를 사용하지 않습니다. 카카오톡 맞춤 공유에만 공식 Kakao JavaScript SDK와 JavaScript 키를 사용합니다. 360~430px 모바일 화면을 우선으로 설계했으며, PC에서는 최대 460px 너비로 중앙에 표시합니다.

**모든 인물, 날짜, 장소, 교통 안내, 연락처, 계좌는 테스트용입니다. 실제 송금·길 찾기에 사용하지 마세요.** 지도는 위치 안내용 일러스트이며 실제 지도 임베드가 아닙니다.

## 실행 방법

### 가장 간단한 방법

`index.html`을 브라우저에서 엽니다. 사진 확대·달력·D-Day·음악 제어는 로컬 파일에서도 동작합니다. 자동 복사 권한이 없는 환경에서는 직접 복사할 수 있는 창이 열립니다. `file://`에서는 로컬 파일 경로를 공유하지 않고 배포 후 이용하도록 안내합니다.

### VS Code 로컬 서버 (권장)

VS Code의 **Live Server** 확장 프로그램이 설치되어 있다면 `index.html`을 우클릭해 **Open with Live Server**를 선택합니다. 별도 빌드는 필요하지 않습니다. `localhost`에서는 브라우저 권한에 따라 자동 복사를 사용할 수 있습니다. 로컬 서버 URL은 다른 사람에게 전달할 공개 주소가 아닙니다.

## 정보 수정 방법

`js/main.js` 맨 위의 **`WEDDING_CONFIG`**에 수정할 데이터를 모았습니다. 문자열은 HTML로 해석되지 않고 텍스트로 표시됩니다.

| 항목 | 수정 위치 |
| --- | --- |
| 신랑·신부 이름, 부모님, 연락처 | `groom`, `bride` |
| 예식 날짜·시간 | `date` — 예: `'2027-05-22T14:00:00+09:00'` |
| 초대 인사말 | `greeting` — 줄바꿈은 `\n`, 문단 구분은 `\n\n` |
| 예식장·홀·주소·지도 검색어 | `venue` (`shortName`도 함께 수정) |
| 정확한 장소로 연결할 지도 공유 URL | `venue.naverMapUrl`, `venue.kakaoMapUrl` |
| 지하철·버스·주차 안내 | `venue.transport` |
| 대표 사진 | `coverImage` |
| 갤러리 사진·대체 텍스트·설명 | `gallery` 배열의 `src`, `alt`, `caption` |
| 배경음악 | `musicSrc` |
| 계좌 그룹과 계좌 목록 | `accounts` 배열 |

달력, 커버 날짜, D-Day, 카운트다운, 페이지 제목은 설정에 맞춰 자동으로 갱신합니다. 해외 기기에서도 **한국 시간(UTC+9)**으로 계산합니다. D-Day는 한국의 날짜 차이, 아래 숫자 카운트다운은 정확한 예식 시각까지 남은 시간입니다. 당일은 축하 문구, 다음 날부터는 함께한 날짜를 표시하며 카운트다운은 0으로 유지합니다.

현재 연락 버튼은 테스트 연락처만 안내하고 전화를 걸지 않습니다. 실제 전화 연결이 필요할 때만 `renderInformation()`의 연락 버튼 처리를 `tel:` 링크로 변경하세요.

JavaScript를 끈 환경과 검색/공유 미리보기에도 최신 정보가 보이도록, 실제 정보로 바꿀 때는 `index.html`의 기본 이름·가족 소개·날짜·장소·`title`·`description`도 함께 수정하세요. JavaScript를 끄면 동적으로 생성하는 달력, 갤러리, 계좌 목록은 표시되지 않습니다.

### 지도에 정확한 장소 연결

`venue.naverMapUrl`과 `venue.kakaoMapUrl`에 각 지도 서비스에서 복사한 **해당 장소의 공유 URL**을 넣으면 검색을 거치지 않고 그 링크로 연결됩니다.

1. 네이버지도와 카카오맵에서 전체 주소로 검색합니다.
2. 장소 상세 화면의 주소가 `경기도 안산시 단원구 광덕1로 171`인 예식장인지 확인합니다.
3. 해당 장소의 공유 기능으로 링크를 복사해 각각 `naverMapUrl`, `kakaoMapUrl` 문자열에 붙여넣습니다. URL 전체를 그대로 넣으세요.
4. 청첩장을 새로고침하고 두 지도 버튼이 올바른 장소를 여는지 확인합니다.

공유 URL이 빈 문자열이면 `venue.mapQuery`로 검색합니다. 현재는 동명 장소 혼동을 줄이도록 전체 도로명주소를 검색어로 사용합니다. `mapQuery`도 비어 있으면 `venue.address`를 사용합니다. 장소 공유 링크는 장소를 표시하며, 길찾기는 지도 서비스에서 선택할 수 있습니다. 별도의 API 키는 필요하지 않습니다.

### 사진 추가

1. `images/`에 `cover.jpg`, `photo-01.jpg` 등의 파일을 추가합니다.
2. 설정을 `coverImage: './images/cover.jpg'`처럼 변경합니다.
3. 갤러리 각 항목의 `src`를 `'./images/photo-01.jpg'`로 지정합니다.
4. 각 사진 내용을 설명하는 `alt`와 원하는 `caption`을 작성합니다.

빈 경로 또는 잘못된 파일 경로는 로컬 꽃 일러스트로 대체되어 레이아웃이 유지됩니다. 사진은 `object-fit: cover`로 잘리므로 중요한 피사체를 중앙에 두세요. 필요하면 `css/style.css`에서 해당 사진의 `object-position`을 조정하세요. 모바일 로딩을 위해 긴 변 1600px 내외의 최적화된 JPG/WebP를 권장합니다. 갤러리는 배열 항목을 추가·삭제해 개수를 조절할 수 있습니다.

### 음악 추가

1. 사용 권한이 있는 MP3를 `music/wedding.mp3`에 추가합니다.
2. `musicSrc`를 `'./music/wedding.mp3'`로 변경합니다.
3. 커버의 **BGM OFF** 버튼을 직접 눌러 재생합니다. 다시 누르면 일시정지합니다.

자동 재생하지 않으며, 사용자가 누르기 전에는 음악 파일 요청도 하지 않습니다. 파일이 없거나 재생에 실패하면 안내 메시지를 표시합니다. 초기 빈 경로에서는 음악 준비 중 메시지를 표시합니다.

### 색상과 디자인

`css/style.css` 상단 `:root`의 `--paper`, `--ivory`, `--ink`, `--accent` 등을 변경하면 전체 색상을 바꿀 수 있습니다. CSS와 JS는 기능별 주석으로 구분했습니다. 기기의 기본 명조/고딕 폰트를 사용해 네트워크 연결 없이도 표시됩니다.

## 카카오톡 맞춤형 공유 설정

공유 섹션의 기존 **카카오톡으로 공유** 버튼이 `Kakao.Share.sendCustom()`으로 카카오디벨로퍼스에 저장된 사용자 정의 메시지 템플릿 **138398 (피드 A형)**을 사용합니다. 이미지·제목·설명·버튼과 이동 링크는 템플릿에 저장한 설정을 그대로 사용합니다. 기존 OG 메타 태그와 청첩장 링크 복사 기능은 유지합니다. URL을 채팅창에 직접 붙여넣었을 때의 미리보기는 기존 OG 정보를 사용합니다.

### 1. JavaScript 키 입력

카카오디벨로퍼스에서 앱을 선택하거나 새 앱을 만듭니다. **[앱] → [플랫폼 키] → [JavaScript 키]**에서 복사한 키를 `js/main.js`의 **`KAKAO_SHARE_CONFIG.javascriptKey`**에 입력합니다.

```js
const KAKAO_TEMPLATE_ID = 138398; // 저장된 사용자 정의 템플릿 ID (숫자)
const KAKAO_SHARE_CONFIG = {
  javascriptKey: '', // 기존에 입력한 키는 유지. 변경 시 이 위치에서 수정
  templateArgs: {}   // 사용자 인자가 없으면 빈 객체 유지
};
```

JavaScript 키는 브라우저 SDK용 공개 식별자입니다. Admin 키·REST API 키·클라이언트 시크릿·인증 토큰은 넣지 마세요. 사용자 정의 공유에는 해당 템플릿을 등록한 앱의 JavaScript 키와 템플릿 ID가 필요합니다. 카카오 로그인·액세스 토큰·백엔드는 필요하지 않습니다. 이번 변경에서는 기존 JavaScript 키를 수정하지 않았습니다.

### 템플릿 ID와 사용자 인자

템플릿 ID는 `js/main.js`의 **`KAKAO_TEMPLATE_ID`** 상수에서 설정합니다. 현재 값은 숫자 `138398`입니다. 해당 템플릿의 사용 목적이 **카카오톡 공유**이고 최신 편집 내용이 저장되어 있는지 확인하세요.

템플릿에 사용자 인자가 없다면 `templateArgs: {}`를 유지하세요. 이 경우 SDK 요청에서 `templateArgs`를 생략하고 저장된 템플릿 내용만 사용합니다. 이미지·제목·설명·버튼은 프론트엔드에서 별도로 덮어쓰지 않습니다.

예를 들어 템플릿에 `${NAME}` 인자를 정의했다면 다음과 같이 해당 인자만 설정합니다.

```js
templateArgs: {
  NAME: '효원 & 미래'
}
```

키 이름은 템플릿의 사용자 인자 이름과 대소문자까지 일치해야 하며 `${}`를 제외한 이름으로 작성합니다. 값은 문자열로 넣으세요. 위 `NAME`은 예시이므로 실제 템플릿에 정의하지 않았다면 추가하지 않습니다. 필요한 인자가 여러 개라면 같은 객체에 모두 추가합니다. 사용자 인자가 있는 템플릿에서는 그에 맞는 값을 직접 채워야 합니다. 규격은 [카카오 사용자 정의 공유 문서](https://developers.kakao.com/docs/ko/kakaotalk-share/js-link#custom-template-msg)를 참고하세요.

### 2. JavaScript SDK 도메인 등록

**[앱] → [플랫폼 키] → 사용하는 [JavaScript 키] → [JavaScript SDK 도메인]**에 SDK가 실행될 웹사이트의 오리진을 등록합니다.

- 운영: `https://tome829.github.io`
- Live Server 예시: `http://127.0.0.1:5500`
- localhost로 접속한다면 별도로 `http://localhost:5500`

`/wedding_invitation/` 경로는 도메인 등록값에 포함하지 않습니다. 로컬 주소의 호스트와 포트는 실제 브라우저 주소와 일치시켜 주세요. `file://`로는 이 기능을 테스트하지 않습니다.

### 3. 제품 링크 도메인 등록

**[앱] → [제품 링크 관리] → [웹 도메인]**에 `https://tome829.github.io`를 등록하고 필요하면 기본 웹 도메인으로 선택합니다. 이 설정은 메시지 안의 이미지·제목 및 버튼 링크가 열리는 사이트를 지정하며, 위의 SDK 도메인 등록과 별도로 필요합니다. 코드의 실제 이동 URL에는 `/wedding_invitation/` 경로가 포함됩니다.

설정 경로는 [카카오 공식 공유 튜토리얼](https://developers.kakao.com/docs/ko/tutorial/js-share)을 기준으로 작성했습니다.

### 4. 템플릿 이미지·링크와 SDK

- 대표 이미지·제목·설명·버튼은 카카오디벨로퍼스의 **메시지 템플릿 138398**에서 수정하고 저장합니다. 로컬 이미지 파일과 기존 OG 메타 태그는 변경하지 않았습니다.
- 템플릿에 업로드하거나 지정한 이미지가 사용됩니다. `images/kakao-cover.jpg`는 보관되어 있지만 코드에서 이 파일의 URL을 별도로 전송하지 않습니다.
- 템플릿의 모바일 웹·PC 웹 링크와 버튼 링크가 `https://tome829.github.io/wedding_invitation/`로 설정되어 있는지 확인하세요. 코드에서 이동 URL을 덮어쓰지 않습니다.
- 실제 카드의 사진 크롭·여백·크기는 저장된 템플릿과 카카오톡 앱 버전에 따라 달라집니다.
- 2026-10-26에 [공식 다운로드 페이지](https://developers.kakao.com/docs/ko/javascript/download)에서 확인한 최신 SDK **2.8.4**를 공식 CDN과 SRI 무결성 해시로 불러옵니다. 버전을 바꿀 때 URL과 `integrity` 값을 함께 교체하세요.
- SDK는 기존 `index.html`의 스크립트 한 개로만 비동기 로딩하며 클릭할 때 초기화 여부를 확인합니다. 별도 스크립트를 삽입하거나 SDK를 중복 초기화하지 않습니다. 공유 요청은 팝업 차단을 줄이도록 클릭 핸들러에서 동기적으로 호출합니다.

### 5. 테스트 방법

개발용 자동 검증은 Node.js가 설치된 환경에서 `node ./tests/kakao-share.test.cjs`로 실행합니다. 외부 패키지 없이 SDK를 대체해 템플릿 ID와 사용자 인자 전달, 저장된 콘텐츠 유지, SDK 단일 로딩·중복 초기화 방지, 키 미설정·SDK 누락·예외 처리를 검사하며 실제 메시지는 보내지 않습니다.

1. 템플릿 138398을 등록한 앱의 JavaScript 키와 두 종류의 도메인 등록을 확인합니다. 사용자 인자가 있다면 실제 이름에 맞춰 `templateArgs`를 채웁니다.
2. Live Server 등 등록한 HTTP 로컬 서버로 페이지를 엽니다. 카카오디벨로퍼스에 템플릿이 저장되어 있고 이미지·버튼 링크가 설정되어 있어야 합니다.
3. **카카오톡으로 공유**를 누르고 대상 선택 화면이 열리는지 확인합니다. PC에서는 카카오계정 로그인 화면이 나타날 수 있습니다.
4. 직접 본인의 테스트 채팅방을 선택해 전송하고 템플릿 138398에 저장한 대표 사진·제목·설명·버튼이 그대로 표시되는지 확인합니다. 사용자 인자가 있다면 입력한 값으로 치환되는지도 확인합니다.
5. 이미지·제목과 버튼을 눌러 모두 `https://tome829.github.io/wedding_invitation/`로 이동하는지 확인합니다. Android/iOS 실제 기기에서도 확인하세요.
6. 공유 취소 후 기존 링크 복사·갤러리·음악 버튼이 계속 동작하는지 확인합니다. 공유 창이 열린 것만으로 전송 완료 메시지는 표시하지 않습니다.
7. 키가 비어 있으면 준비 중 안내가, SDK 로딩이 실패하면 링크 복사를 권하는 안내가 표시됩니다. 둘 다 다른 청첩장 기능은 계속 동작합니다.

자동 검증은 SDK 요청과 오류 처리를 확인하며, 카카오에 저장된 템플릿의 실제 내용·앱 소유 관계·도메인 설정·전송 결과는 직접 확인해야 합니다. 템플릿 오류가 나오면 ID, 템플릿을 등록한 앱의 키, 사용 목적, 저장 여부, 사용자 인자를 확인하세요. 도메인 오류가 나오면 SDK 실행 도메인과 제품 링크 도메인을 각각 확인하세요. SDK에서 동기적으로 발생한 오류는 안내하지만 별도 카카오 창에서의 인증 오류나 사용자의 전송 취소는 전송 성공으로 판정하지 않습니다. 자세한 API 규격은 [카카오톡 공유 JavaScript 문서](https://developers.kakao.com/docs/ko/kakaotalk-share/js-link)를 참고하세요.

## 구현 기능 및 접근성

- 한국 시간 기준 달력·D-Day·초 단위 카운트다운
- 갤러리 확대, 이전/다음 버튼, 좌우 방향키, Escape 및 배경 클릭 닫기
- 네이티브 `dialog`의 포커스 관리, 키보드 포커스 표시, 이미지 대체 텍스트
- 계좌 접기/펼치기, 계좌번호·주소·현재 청첩장 URL 복사
- 클립보드 API 미지원/권한 거부 시 선택 가능한 직접 복사 창
- 음악 수동 재생/일시정지 및 실패 안내
- `IntersectionObserver` 스크롤 등장 효과와 `prefers-reduced-motion` 지원
- 지도 서비스의 검색 링크 (새 창), 위치 안내용 더미 일러스트

복사 API는 HTTPS 또는 localhost 등 보안 컨텍스트와 브라우저 권한이 필요합니다. 현재 청첩장 링크는 해시(`#...`)를 제거해 복사하며, URL의 쿼리 문자열은 유지합니다. 공유 시 URL에 개인정보나 인증값을 넣지 마세요.

## 로컬 확인 체크리스트

1. 360px, 390px, 430px 및 PC 너비에서 가로 넘침과 글자 잘림을 확인합니다.
2. 달력의 예식일 표시, 예식 전·당일·예식 후 D-Day를 확인합니다.
3. 갤러리 버튼, 좌우 방향키, Escape, 닫은 뒤 포커스 복귀를 확인합니다.
4. 계좌 펼치기와 복사, 주소 복사, 링크 복사 및 권한 거부 시 직접 복사를 확인합니다.
5. 사진·음악 경로가 비어 있거나 잘못되어도 화면과 버튼이 정상인지 확인합니다.
6. 음악 파일 추가 후 실제 모바일 기기에서 재생·일시정지를 확인합니다.
7. 기기의 모션 줄이기 설정과 키보드 Tab 탐색을 확인합니다.
